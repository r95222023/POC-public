# PhotoGroup-132：密集重建、貼圖與離群點投影

實測日期：2026-11-09。接續 [34 張照片的稀疏重建](photogroup132-sparse.md)，使用官方 OpenMVS 2.4.0 Windows CPU 發行檔。使用者提供的 iTwin 模型未作為重建或貼圖輸入。

## 設定與成果

去畸變影像長邊 1280、深度圖長邊上限 640、2 個 CPU 執行緒、4 個鄰近視角、融合至少 3 個視角同意、關閉 tower-mode。網格上限約 10 萬面，不補洞；貼圖使用去畸變照片，最大貼圖 4096。

| 項目 | 本次成果 |
|---|---:|
| 使用已定位照片 | 34 |
| ROI 內融合密集點 | 201,123 |
| 網格幾何頂點 | 50,035 |
| 三角面 | 99,953 |
| 貼圖 | 1 張，4096×4096 |
| 內嵌貼圖 GLB | 9,701,076 bytes |
| 可疑點貼回表面 | 1,053 |
| 保留原座標的其他點 | 14,001 |

可疑點以觀測次數、重投影誤差與鄰近密度標記，不依離地高度分類。將其投影到網格的最近三角面，另存新點雲；地面與屋頂各自保留其重建高度，不將整個場景壓平。原始 COLMAP 模型與點雲保持原樣。

## 已處理的銜接與貼圖問題

OpenMVS ReconstructMesh 在此流程產生 PLY 網格，貼圖入口使用密集場景 `scene_dense.mvs` 搭配 `-m scene_mesh.ply`，不假設會另外產生含網格的 MVS 專案。

本機、此資料與此發行檔組合中，預設貼圖後處理使有效三角區接近全黑。OBJ 與 GLB 交叉檢查皆可重現；停用全域／局部接縫亮度調整與銳化後恢復正常。以各面 UV 中心進行最近像素取樣，全黑比例由約 98.64% 降至 0%。目前 CLI 明確採用停用設定，代價是可能保留照片接縫；尚未進一步分辨三項後處理中各自的影響。

原生 OpenMVS GLB 仍引用外部 PNG。交付的 `model.glb` 已將貼圖嵌入，驗證內嵌貼圖像素與來源一致，單檔即可下載；原生輸出另留作本機診斷。

## 驗證範圍

- 重新讀取網格與 GLB，確認兩者座標範圍一致，所有網格座標皆有限。
- 確認未標記點的原始／修整 JSON 座標一致；已投影點到網格表面的最大剩餘距離約 `6.9e-7` 個未校正重建單位，屬數值檢查，不能當成實際測量精度。
- 從最終 GLB 的實際頂點、面與貼圖產生影像並目視檢查，可辨識屋頂、階梯、道路與河岸。
- **23 項自動測試通過**，涵蓋相機分組、ZIP 路徑、離群點篩選與最近三角面投影；地面與屋頂的投影測試各自貼回對應表面。
- 稀疏預覽的篩選與相機顯示切換通過離線 DOM 模擬，貼圖預覽 JavaScript 語法檢查通過；頁面、模型、JSON 與所有 Three.js 模組的本機 HTTP 檢查為 200。尚未完成真實瀏覽器 WebGL 互動自動驗證。

本機產物位於 `outputs/photogroup132/sift-cpu-1600/surface/`，包括 `model.glb`、`preview.html`、`model-preview.png`、修整 PLY、原始／修整 JSON、完整命令／設定與各階段日誌；這些照片、模型與衍生影像均不推送 GitHub。

## 限制與接續

這是低解析度 CPU 實驗，不是工程精度驗收。比例尺與世界座標未校正，未與 iTwin 模型配準或比較表面距離；屋簷、遮擋、植被、動態水面與場景邊界仍可失真或缺漏。將可疑點貼回表面是視覺修整，表面本身若錯誤，投影亦可能錯誤。

重現命令、官方套件安裝與相同來源／設定的 `--resume` 方式見 [主 README](../README.md#密集重建貼圖與離群點表面投影)。未來提高解析度前，宜先用較大記憶體的重建主機，並以實際尺寸或控制點建立尺度與獨立檢查。
